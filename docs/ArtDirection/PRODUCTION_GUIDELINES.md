# Производство, состав пакета и проверка

20.10.2026. Итоговое направление: **Простая игровая 3D-стилизация в стиле Schedule I; конкретный дизайн и контент — собственные.** Этот пакет — художественная разработка. Он не заменяет production assets, gameplay rules, действующий UI и карту города.

## Что переиспользовать, что изготовить

| Уже существует | Переиспользовать | Для текущего направления потребуется отдельно |
|---|---|---|
| URP 17.6.0, настройки света и материалы | Текущий pipeline и shader family, спокойный синий prop | Подобрать значения под общий образец без автоматического пересоздания материалов |
| Стол, ящик, фонарь, прибор, батарея из FirstDeal builders | Масштаб, части, pivots, принципы разбиения | Свести к единым простым мешам, проверить городской collider/held-позу |
| Runtime боксы CityTradeView | Привязки ID, видимости, света, доков и стола | Подключить визуальные prefab отдельно, не менять операции владения |
| WorkshopSession и Changed/TransactionCompleted | Результат операции, диагностику, деньги, сроки | Представления статусов, анимации и звук без второго источника истины |
| uGUI и Input System UI | Canvas, safe area, модальность, существующие взаимодействия | Перестроить один экран и проверить focus/reflow; не переходить на новый framework |
| WorldSignFont/существующий sign shader | Осмысленные физические вывески | Общий размер/контраст, единые русские названия и экранный дубль мелких надписей |
| Прототипные NPC / Male_Casual | Временный placeholder после проверки лицензии/рига | Одна базовая фигура простого стиля и три варианта; не 20 уникальных людей |
| Текущие props/сохранение/карта | Городской цикл и реальные ограничения | Полный новый интерфейс истории/развития пока только дизайн |

Сложные mesh assets без установленной лицензии не объявляются бесплатными для релиза. Все изображения нового пакета созданы встроенным imagegen, SVG/HTML — исходный дизайн этой задачи. Чужие Schedule I screenshots даны ссылками и не включены в игру/репозиторий. Полные промпты сохранены в [sources/PROMPTS.json](sources/PROMPTS.json).

## Технические рабочие бюджеты после аудита URP

Ниже **стартовые лимиты для первого художественного образца**, не измеренные пределы движка/4060 Ti и не универсальный triangle budget. Приоритет — силуэт на реальной дистанции и число видимых объектов/материалов. Увеличивать бюджет только после сравнения кадра и профиля.

| Категория | Начальный ориентир | Материалы/текстуры | Проверка смысла затрат |
|---|---|---|---|
| Фонарь hero | 600–1800 triangles; общий mesh на три экземпляра | 1–2 материала, общий 512–1024 atlas при необходимости | Ручка/опора не ломаются на 0,75–1,1 м; микровинт не оправдывает draw call |
| Прибор, батарея, ящик | 150–900 на объект по силуэту | Общая палитра/атлас, без отдельного 2K на каждый | Захват/вставка/клеммы узнаваемы, сортировка прозрачности не нужна |
| NPC | 2500–6000 на базовое тело с одеждой | 1–2 материала, один 1024 atlas; один риг | Суставы и лицо читаются на дистанции сделки; крупные глаза не доминируют |
| Модуль помещения | 50–600 на стену/стойку; сложный проём отдельно | Повторяемые материалы, 512–1024 tile | Не видно отдельных граней сглаживания; коллайдер не копирует мелкие детали |
| Дальнее здание | 100–800 на простой объём | Общая палитра, минимум submeshes | Силуэт/вход/район различимы; детали не исчезают в субпикселях |
| UI/графика | Иконки SVG master 24/32; импорт растром/мешем по выбранному пути | Один согласованный atlas, без эффекта на каждую кнопку | Нет лишнего overdraw и перехвата raycast декоративными элементами |

Текущее направление не требует прозрачной линзы, realtime reflection на каждом пропе, нового renderer feature, полнокадрового outline, volumetrics или API-генерации ассетов. Исследовательские варианты реализма, comic/cel и технического альбома не входят в действующее производство. Не добавлять контур или иной художественный рендер ради отличия от Schedule I: собственными должны быть конкретные модели и композиция при сохранении похожего стиля.

## Производственный маршрут по уточнённому направлению

1. Создать один изолированный prefab фонаря и отдельную ArtTest scene **по следующему заданию**, не менять общий город. Зафиксировать 1 м масштабом и текущими городскими габаритами. При отсутствии доступного Blender можно собрать первый образец штатной геометрией Unity; это не заменяет финальную mesh-работу.
2. В этой же сцене поставить существующий стол, три экземпляра, ящик, прибор, один NPC и обычную дверь. Сначала камера 70° и текущая высота, затем свет. Снимать реальные сравнительные кадры с неизменной камеры.
3. Изготовить mesh в доступном DCC, применить единый scale/transform, проверить pivot внизу и точку хвата, нормали, UV, материалы. Импортировать FBX/GLB доступным проекту путём с контрольным размером; конкретный exporter не объявляется настроенным до проверки. Метафайлы создаёт Unity, существующие GUID не пересоздавать.
4. Настроить четыре состояния знания на одном визуальном экземпляре; неисправность не меняет внешний mesh до теста. Проверить включение, тест, ремонт, повторный тест и продажу на модели текущего проекта.
5. Перенести один UI flow: предложение → выбор предъявления → результат. Сохранить существующую паузу, возврат фокуса, отмену и проверку достижимости точки. Анимации только после корректной передачи результата модели.
6. Пройти реальные маршруты и узкое регрессионное покрытие затронутых мест. Затем решить, распространять ли стиль на другие зоны. Не строить весь город из нового набора до одного принятого образца.

Сначала сохранить исходные editable mesh/texture files и лицензию, затем производный импорт. Визуальные docs не складывать под Assets: это исключает ненужный Unity-импорт. Временные снимки/пробы — `Temp/ArtDirection`, уже игнорируются. В Git остаются семь выбранных растров (включая отклонённый A и исходный Unity capture), SVG, HTML, font/OFL и исходники; черновики и сетевые референсы не копируются. Количество растра проверять по факту манифеста, а не наращивать при каждом запуске.

### Оценка труда

Предварительная оценка для одного разработчика, без гарантии и без платных ассетов: фонарь/ящик/прибор 6–12 ч; одна маленькая среда/свет 5–10 ч; базовый NPC и варианты 8–16 ч; один интегрированный UI flow 6–12 ч; проверка/исправления 4–8 ч. Итого первая принятая Unity-проба порядка **29–58 рабочих часов**. Это не оценка всего города или игры. Риг/анимации и доступность DCC — главные неизвестные; AI-растр сам по себе не сокращает их до нуля. Не переносить эти часы в обещание срока без отдельной оценки исполнителя.

### Восстановление образцов

Из корня репозитория: `python docs/ArtDirection/sources/build_samples.py`. Только Python standard library и уже имеющийся файл шрифта. Скрипт восстанавливает 12 SVG UI, 4 SVG sheets и `index.html`; imagegen PNG из промптов не воспроизводятся детерминированно и не перегенерируются автоматически. HTML работает локально, не требует сервисов или публикации. Для браузерного просмотра можно открыть его локально; через HTTP также работают ссылки на Markdown и font.

Статический аудит: `python docs/ArtDirection/sources/verify_samples.py`. Он проверяет файлы/локальные ссылки, SVG XML, кириллицу в cmap локального TTF, контраст выбранных пар и согласованность действующего направления. Это не screenshot-test и не Unity test.

Для локального растра SVG есть `sources/render_samples.cjs`: передать первым аргументом путь к уже установленному `node_modules` с `sharp` из workspace dependencies. Он ничего не скачивает и сохраняет только временные PNG в `Temp/ArtDirection`. Никакой новый браузер, сервер или пакет для этого не устанавливается.

## Протокол верификации этой задачи

Заполненные наблюдения и незакрытые проверки — в [VALIDATION.md](VALIDATION.md). До переноса в Unity статус художественной реализации — **не проверена в игре**. Существующие журналы S2/S3/S4 не подтверждают новый визуал.

Для будущего Unity-образца обязательны: кадры одной камеры до/после, одно действие всех важных состояний, отказ частичной передачи, повтор оплаты, локальный фокус/Esc, 16:9/16:10/21:9, реальный размер текста, 125%/150%, UI без цвета/без звука и фактический Player profile с условиями. В этой задаче запускать экономические тесты, сборку Player или выпускать ZIP не требуется: gameplay код и сцены не изменялись.
